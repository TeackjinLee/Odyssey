# 걷기·달리기 12프레임 요청 키트

오디세우스에서 통한 걷기·달리기 요청 방식을 **다른 캐릭터**에도 그대로 쓰려고 묶어 둔 것이다.
처음 걷기를 받았을 때 발이 땅에서 미끄러지고 팔이 가슴 앞에 굳어 있었는데, 방향마다 "움직임 안내 그림"을 붙여
받았더니 해결됐다. 달리기도 같은 방법이다. 오디세우스 쪽 진행 기록은 `../OUTFIT.md`.

## 들어 있는 것

| 위치 | 내용 |
|---|---|
| `guides/walk12_<방향>.png`, `guides/run12_<방향>.png` | 방향 S SE E NE N의 12장 막대 그림 안내(빨강=오른다리, 파랑=왼다리, 짙은 색=팔·주먹). 캐릭터와 무관해 그대로 쓴다 |
| `walk12_prompt.txt`, `run12_prompt.txt` | 요청 글 틀. `__CHARACTER__`(인물 설명), `__FACING__`(방향), `__EXTRA__`(방향별 덧붙임)를 채운다 |
| `odysseus_character.txt` | 인물 설명 예시. 새 캐릭터는 이 형식으로 두 줄 써서 바꾼다 |
| `examples/odysseus_walk.webp`, `examples/odysseus_run.webp` | 방향마다 **pose.png(넣은 그림) · guide.png(붙인 안내) · 받은 결과**를 한 장에 모은 예시. 어떤 그림을 받아야 하는지 기준으로 본다 |

## 새 캐릭터에 쓰는 순서

1. 캐릭터의 기본 8방향 시트를 먼저 받는다(칸 384×512, 윗줄 N NE E SE / 아랫줄 S SW W NW).
2. 인물 설명 파일을 쓴다(체형·머리·옷·장비 없음 여부, 영어 두세 줄).
3. 요청 폴더를 만든다.
   ```bash
   python3 tools/motion_request.py <기본 8방향 시트> <인물 설명.txt> <출력 폴더> both 1
   ```
   방향마다 후보 1장씩(`walk_SEa` …, 더 받으면 `b`)의 `pose.png`·`guide.png`·`prompt.txt`와 `run.sh`가 생긴다.
4. `<출력 폴더>/run.sh`를 돌린다(Codex가 방향·후보를 동시에 받는다. **후보는 1장씩만 받고** 아래 "한도 아끼기"를 따른다).
   끝나면 출력된 경로의 그림을 `assets/source/<캐릭터>_<동작>_<방향>.webp`로 저장한다(RGB, 무손실).
5. 후보를 고른다: 땅이 움직이는 미리보기에서 **디딘 발이 한 장마다 뒤로 가는지, 팔이 다리와 반대로 흔들리는지,
   12장 내내 몸 돌림·키·머리 크기가 같은지**를 본다. 고를 때 쓴 기준은 아래 "받아 본 교훈".
6. 8방향 한 장으로 묶고 시트를 만든다: `tools/pack_strip.py`(걷기는 키 맞춤, 달리기는 뜬 높이 살림)와 `tools/gen_hero.py`.
   첫 프레임 주먹 위치(`STRIP_HANDS`)는 묶인 시트에 격자를 얹어 보고 찍는다.

안내 그림은 `python3 tools/walk_guide.py <출력.png> <앞 x> <앞 y> <오른쪽 x> <오른쪽 y> [back] [run]`로 다시 그릴 수 있다
(체형이 아주 다른 캐릭터면 `L, TH, SH, HIP` 상수를 조정). 값은 파일 머리 설명에 있다.

## 한도 아끼기: 한 장에 여러 개 받기

Codex(이미지 생성)는 **요청 한 번마다 한도가 줄어든다.** 방향마다 한 장씩 받으면(공격 4종 × 5방향 × 후보 2장 = 40번) 한 번에
다 날아가 하나도 못 받는다(실제로 40개가 전부 한도에 걸렸다). 그래서 **이미지 한 장에 여러 방향(줄)을 담아 받는다.**

- **원칙:** 한 장은 1536×1024, 열 = 프레임, 줄 = 방향. 칸 크기가 걷기(384×341)와 비슷하게 남도록 줄 수를 정한다.
  칸이 작아질수록 그림이 뭉개지고 손이 안 보이니, 더 촘촘히 담지는 않는다.
- **공격(기본이 이 방식):** `python3 tools/motion_request.py <기본 시트> <인물> <출력> attack1,attack2,attack3,heavy 1`
  - attack1·2(4장)·attack3(5장): 한 장에 3방향(E·SE·S / NE·N) → 동작마다 2번
  - heavy(6장, 팔을 벌려 가로로 넓다): 한 장에 2방향(E·SE / S·NE / N) → 3번
  - 합쳐 **후보 1장씩 9번**(방향마다 따로 받으면 20번). 안내 그림도 같은 칸 배치로 그려 붙인다(`tools/attack_guide.py <출력> <동작> E,SE,S`).
- **받은 뒤:** `python3 tools/split_rows.py <받은 그림> <동작> E,SE,S .`로 줄마다 방향 파일로 자르고(`assets/source/odysseus_<동작>_<방향>.webp`),
  `python3 tools/pack_strip.py . <동작> <프레임 수> 1`로 묶는다. 후보는 **방향별로 마음에 안 드는 줄만** 다시 받는다.
- **걷기·달리기(12프레임):** 방향 하나가 이미 한 장(4×3칸)이라 그대로 두는 게 안전하다. 한도가 아주 빠듯하면
  한 장에 2방향을 6열×4줄(칸 256×256)로 받을 수도 있지만 뭉개져서 권하지 않는다. 대신 **후보를 1장씩만** 받고 흠이 있는 방향만 다시 받는다.
- 어느 쪽이든 후보는 한 번에 많이 받지 말고, 요청을 10개 안팎으로 나눠 돌린다. 한도가 걸리면 로그의
  `try again at ...` 시각이 풀리는 때다(`run.sh`가 만든 `.log`에서 확인).

## 받아 본 교훈 (요청 글에 이미 반영됨)

- 안내 그림이 없으면 다리를 늘 벌리거나 거의 안 움직인다. 안내 그림이 가장 효과가 컸다.
- 대각선(SE·NE)은 장마다 몸이 앞쪽으로 돌아간다 → "12장 모두 같은 만큼 돌린 채"를 넣는다(`__EXTRA__`).
- 칸마다 캐릭터 키가 달라지면 머리가 깡충거린다 → "세 줄 모두 같은 크기·머리 크기"를 넣는다.
- 북(N)은 가만히 미끄러지듯 걷는다 → 발을 크게 벌리고 든 발바닥이 보이게 요청한다.
- 달리기는 두 발이 다 뜨는 3장을 안내 그림에 넣어 두어야 "빨리 걷기"가 되지 않는다.
- 후보는 1장씩 받고, 같은 요청에도 가끔 섞이는 얼룩·소품 잘못 같은 흠이 있는 방향(줄)만 다시 받는다.
- 서쪽 세 방향(W NW SW)은 받지 않고 동 쪽 줄을 좌우로 뒤집는다(`STRIP_MIRROR`).
